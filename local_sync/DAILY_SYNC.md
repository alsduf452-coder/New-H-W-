# 매일 09:00 자동 동기화 + 앱 버튼 수동 요청

새 앱 전용 기능입니다. 기존 서버/앱은 변경하지 않습니다. 최초 자동 예약은 PC에서 설정하며, 앱 버튼 수동 요청은 아래 업데이트 절차에 따라 새 수신 서버 재배포가 필요합니다.

## 고정 폴더의 의미

고정 위치로 옮기는 것은 Excel이 아니라 **동기화 프로그램 폴더**입니다. 예: `C:\Users\IRAUser\HW_Excel_Sync`.
`agent.py`, `daily_sync.py`, `run_daily.ps1`, `manage_schedule.ps1`, `manage_schedule.bat`, `install.bat`, `requirements.txt`, 기존 `config.toml`을 포함한 local_sync 폴더 내용을 이 위치에 두세요. Temp는 임시 폴더이므로 사용하지 않습니다.
Excel 3개는 Q드라이브에 유지할 수 있습니다. 경로가 바뀌지 않았다면 config.toml을 수정하지 않습니다. 토큰과 설정이 없는 새 ZIP으로 기존 config.toml을 덮어쓰지 마세요.

## 설치

1. 실행 중인 start.bat 동기화를 Ctrl+C로 종료합니다.
2. classic-cloud 브랜치의 최신 local_sync 폴더 내용을 고정 폴더로 복사합니다. 기존 config.toml도 복사합니다.
3. **새 폴더에서 install.bat 실행**: .venv는 경로를 포함하므로 기존 .venv를 복사해 사용하지 마세요. 복사했다면 새 고정 폴더의 .venv만 제거 후 재설치합니다.
4. manage_schedule.bat 실행 → **1번**을 선택합니다. 새 서버 hw-excel-sync-classic의 SYNC_TOKEN을 한 번 입력합니다.
5. **6번**으로 NextRunTime이 다음 09:00인지 확인합니다. Windows 시간대를 `(UTC+09:00) 서울`로 설정하세요.
6. **0번**으로 닫습니다. 이후 창을 열어둘 필요 없습니다.

Windows 작업 스케줄러에 `HW-Excel-Classic-Daily-0900`이 등록됩니다. 로그인한 현재 사용자 권한으로만 실행합니다. 관리자 권한이나 Windows 로그인 비밀번호를 저장하지 않습니다. 회사 정책이 작업 등록 또는 PowerShell 스크립트를 차단하면 담당자에게 허용을 요청하세요. 보안 정책을 해제하지 마세요. 실행 프로세스에만 RemoteSigned 정책을 지정하며 시스템/사용자 영구 정책은 변경하지 않습니다. 회사 그룹 정책은 우회하지 않습니다. 다운로드된 스크립트가 차단되면 출처를 확인한 뒤 파일 속성의 차단 해제를 사용하거나 담당자에게 문의하세요.

## 부재/일시정지

manage_schedule.bat 실행 후 번호 선택:

| 번호 | 기능 |
|---|---|
| 1 | 예약 등록 또는 토큰 교체 |
| 2 | 동기화 일시정지 |
| 3 | 일시정지 해제 (부재 기간은 계속 적용) |
| 4 | 부재 시작일/종료일 추가: YYYY-MM-DD, 양 끝 날짜 포함 |
| 5 | 등록한 부재 기간 모두 제거 |
| 6 | 설정과 예약 상태 확인 |
| 7 | 예약 작업 제거 |
| 0 | 종료 |

로그: `daily-state\YYYY-MM.log`. 토큰 해독/Python 시작 오류: `daily-state\launcher.log`.

## 실행 규칙

- 매일 09:00, 주말 포함. 09:00분 안에 시작된 예약 작업만 전송합니다.
- PC 종료, 절전, 로그아웃 시 실행하지 않습니다. 로그인/복귀 시 밀린 작업을 실행하지 않습니다.
- 화면 잠금은 로그아웃이 아닙니다. 잠금 중에도 실행될 수 있으므로 부재 기간/일시정지를 설정하세요.
- 부재 여부는 연결 실패로 추정하지 않습니다.
- 파일 3개를 순서대로 처리하며 변경 없는 파일은 전송하지 않습니다.
- 실패하면 남은 파일도 중단합니다. 이미 전송된 파일은 유지됩니다. 실패 후 그날 다시 실행해도 재시도하지 않으며 다음 날 09:00에 다시 시도합니다.
- 프로그램은 요청 응답을 기존 타임아웃 동안 기다리지만 자동 재시도하지 않습니다. Render 무료 서버의 기동 지연 등으로 실패하면 그날은 건너뜁니다.
- 실행 중 일시정지/부재 설정 변경은 다음 실행부터 적용됩니다.
- Q드라이브는 이 사용자 세션에서 접근 가능해야 합니다. 예약 실행에서 드라이브를 찾지 못하면 실제 `\\서버\공유폴더\파일.xlsx` 경로를 확인해 config.toml에 넣습니다. 공유폴더 권한/인증도 필요합니다.

토큰은 Windows DPAPI로 암호화되어 `token.dpapi`에 저장되고, 실행 시 자식 프로세스 환경변수로만 전달합니다. 같은 PC의 같은 Windows 사용자로 실행해야 합니다. 새 PC/계정에서는 1번으로 다시 등록하세요. 암호화 파일과 실행 로그도 GitHub에 올리지 마세요.

예약만 사용할 때 기존 start.bat을 켜두지 마세요. start.bat은 별도 수동 연속 동기화 프로그램이며 부재/일시정지 설정을 따르지 않습니다.

검증: Linux에서 예약 판단·부재·일일 중복 방지·실패 중단을 자동 테스트했습니다. Windows 작업 스케줄러 등록과 DPAPI는 실제 사용자 Windows에서 첫 등록/실행 확인이 필요합니다.

## 앱 버튼 수동 동기화 (CLASSIC-CLOUD-04)

자동 09:00 예약에 추가로, 앱의 **최신 데이터 새로고침** 버튼이 서버에 수동 요청을 등록합니다. PC의 별도 작업 `HW-Excel-Classic-Manual-Requests`가 매분 요청만 확인하며 요청이 있을 때만 Excel을 읽고 전송합니다. 앱 버튼 클릭 자체가 로컬 파일에 직접 접근하지는 않습니다.

### 업데이트 순서

1. **새 서버 hw-excel-sync-classic**을 classic-cloud 최신 커밋으로 배포합니다. 시작 시 별도 요청 상태 테이블을 생성합니다. 기존 main 서버에는 적용하지 않습니다.
2. 새 Streamlit 앱도 classic-cloud 최신 코드가 반영되도록 새로고침합니다. 같은 새 DB를 사용해야 합니다. Secrets에 토큰을 추가할 필요 없습니다.
3. PC local_sync 폴더에 최신 `agent.py`, `daily_sync.py`, `manual_sync.py`, `sync_lock.py`, `run_daily.ps1`, `manage_schedule.ps1`, `manage_schedule.bat`을 복사합니다. 기존 config.toml과 암호화 토큰 파일은 유지합니다.
4. 기존 연속 start.bat은 종료하고, manage_schedule.bat **1번**으로 다시 등록합니다. 같은 새 서버 토큰을 입력합니다. 6번에 자동/수동 작업 2개가 표시됩니다.
5. Excel을 저장한 뒤 앱 버튼을 누릅니다. 대기 중 → 동기화 중 → 완료/실패 상태를 확인합니다. 보통 요청 확인에 최대 약 1분, 여기에 파일 읽기·업로드 시간이 더 걸립니다. 화면은 15초마다 상태를 갱신합니다.

### 실행 제한

- PC가 켜져 있고 같은 Windows 사용자가 로그인되어 있어야 합니다. Q드라이브/공유폴더 접근과 인터넷 연결이 필요합니다. 절전에서 깨우지 않습니다.
- 부재 기간/일시정지 시 수동 요청도 전송하지 않습니다. 이미 실행 중인 요청을 소급 취소하지는 않습니다.
- 확인되지 않은 요청은 5분 후 만료되며 복귀 후 늦게 실행하지 않습니다. 처리 중 요청은 최대 20분 후 앱에서 만료로 표시합니다.
- 중복 버튼 클릭은 처리 중인 같은 요청으로 합칩니다. 여러 사용자/PC가 동시에 요청해도 한 PC만 요청을 가져갑니다.
- 09:00 자동 작업과 수동 작업은 OS 파일 잠금으로 동시 전송하지 않습니다. 수동 요청은 다음 분에 확인합니다. 자동 작업이 수동 작업과 정확히 겹치면 그날 자동 작업은 건너뜁니다.
- 수동 작업의 연결/인증/전송 실패 후 그날은 요청 확인을 중단합니다. 매분 작업이 실행돼도 네트워크 재시도는 하지 않습니다. 다음 날 다시 확인합니다. 로그 daily-state/YYYY-MM.log를 확인하세요.
- 버튼은 실패/부재 상태를 우회하는 기능이 아닙니다. 명시적으로 재요청해도 당일 실패 중단 상태에서는 실행하지 않습니다.
- 정상 상태에서는 PC가 매분 서버에 요청 존재 여부를 확인합니다. 이는 Excel을 매분 업로드하는 동작과 다릅니다.

PowerShell에서 상태 확인:

```powershell
Get-ScheduledTask -TaskName 'HW-Excel-Classic-*' | Format-Table TaskName,State
```

요청·중복·만료·인증 및 PC 실패/부재 동작은 자동 테스트했습니다. Windows 작업 스케줄러와 회사 네트워크에서 실제 클릭→전송까지는 설치 후 확인해야 합니다.
